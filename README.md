# MiniPM

소규모 개발팀과 학생 팀 프로젝트를 위한 **프로젝트 및 이슈 관리 웹 서비스**입니다.

프로젝트별 멤버와 권한을 관리하고, 이슈의 담당자·상태·댓글·해결 내용을 기록할 수 있습니다. 주요 변경 사항은 WebSocket을 통해 관련 사용자에게 실시간으로 전달됩니다.

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | MiniPM |
| 개발 형태 | 개인 프로젝트 |
| 개발 기간 | 2026.09.14 ~ 2026.09.30 |
| 개발자 | 최희조 |

### 개발 목적

- Spring Boot 기반 웹 애플리케이션의 전체 개발 과정 경험
- 회원·프로젝트·이슈·댓글을 통한 CRUD 기능 구현
- 프로젝트별 사용자 역할과 접근 권한 관리
- 상태 변경 이력을 통한 업무 책임과 진행 과정 기록

- 화면부터 데이터베이스까지 이어지는 전체 처리 흐름 학습

## 2. 서비스 특징

### 프로젝트 중심 업무 관리

프로젝트를 생성한 사용자는 자동으로 `ADMIN`이 되며, 가입된 회원을 이메일로 검색하여 프로젝트 멤버로 추가할 수 있습니다.

### 명확한 역할과 책임

이슈 등록자와 담당자를 구분하고, 상태 변경자·변경 시각·해결 내용을 기록하여 업무 진행 과정과 책임을 확인할 수 있습니다.

### 업무 기록 보존

프로젝트, 이슈와 댓글에 논리 삭제 방식을 적용하여 관련 데이터와 변경 이력을 보존합니다.

### 실시간 알림

이슈 등록, 상태 변경, 댓글 등록과 멤버 변경 등의 이벤트를 관련 사용자에게 실시간으로 전달합니다.

## 3. 주요 기능

### 회원 및 인증

- 일반 회원가입
- 아이디·비밀번호 로그인
- Spring Security 기반 인증
- BCrypt 비밀번호 암호화
- 카카오 OAuth2 로그인
- 로그아웃
- 내 정보 조회

### 프로젝트 관리

- 참여 프로젝트 목록 조회 및 검색
- 프로젝트 등록·조회·수정·삭제
- 프로젝트 생성자 `ADMIN` 자동 등록
- 이메일 기반 프로젝트 멤버 추가
- 프로젝트 멤버 목록 조회
- 프로젝트 멤버 제거
- 프로젝트별 `ADMIN`·`MEMBER` 권한 관리

### 이슈 관리

- 프로젝트별 이슈 등록·조회·수정·삭제
- 키워드·유형·상태·우선순위·담당자 검색
- 이슈 유형 관리
  - `FEATURE`
  - `BUG`
  - `TASK`
  - `IMPROVEMENT`
- 우선순위 관리
  - `HIGH`
  - `MEDIUM`
  - `LOW`
- 진행 상태 관리
  - `TODO`
  - `IN_PROGRESS`
  - `DONE`
- 이슈 등록자와 담당자 관리
- 완료 처리 시 해결 내용 기록
- 이슈 논리 삭제

### 상태 변경 이력

- 이전 상태와 변경 상태 기록
- 상태 변경 회원 기록
- 상태 변경 시각 기록
- 동일 상태로의 중복 변경 차단
- `DONE` 변경 시 해결 내용 필수 입력
- 트랜잭션과 행 잠금을 통한 상태·이력 일관성 관리

### 댓글 관리

- 이슈별 댓글 등록
- 작성자 본인의 댓글 수정
- 작성자 또는 프로젝트 `ADMIN`의 댓글 삭제
- 댓글 논리 삭제
- 댓글 등록 시 관련 사용자 알림

### 실시간 알림

- 알림 DB 저장
- WebSocket/STOMP 기반 실시간 전송
- 사용자 전용 알림 채널
- 최근 알림 목록 조회
- 읽지 않은 알림 개수 표시
- 개별 및 전체 읽음 처리
- 행위자 본인 제외
- 중복 알림 수신자 제거
- 연결 실패 시 자동 재연결
- 알림 ID 기준 중복 표시 방지

### 대시보드

- 참여 프로젝트 현황
- 담당 이슈의 상태별 통계
- 담당 이슈의 우선순위별 통계
- 관리 프로젝트별 멤버 수
- 관리 프로젝트별 이슈 현황
- 미지정 이슈 및 완료율 확인

| `PROJECT` | 프로젝트 기본 정보 |

```text
MEMBER 1 ── N PROJECT_MEMBER N ── 1 PROJECT

ISSUE 1 ── N ISSUE_COMMENT
ISSUE 1 ── N ISSUE_STATUS_HISTORY
MEMBER 1 ── N NOTIFICATION
```

## 9. 트러블슈팅

### 상태와 변경 이력의 일관성

이슈 상태 변경에 해결 정보, 상태 이력과 알림 처리가 추가되면서 하나의 요청에서 여러 데이터가 변경되었습니다.

일부 처리만 실패하거나 같은 이슈에 대한 상태 변경 요청이 동시에 발생하면 현재 상태와 변경 이력이 달라질 수 있었습니다.

이를 해결하기 위해 다음 구조를 적용했습니다.

- `@Transactional`을 통한 상태 변경 작업 통합
- `SELECT FOR UPDATE`를 통한 이슈 단위 행 잠금
- 최신 상태 확인 후 변경 이력 저장
- 처리 실패 시 전체 작업 롤백
- 동일 상태로의 중복 변경 차단

### 실시간 알림 전달 안정화

알림 데이터는 DB에 저장되지만 화면에 표시되지 않거나 첫 알림 이후 수신이 중단되는 현상이 발생했습니다.

문제를 다음 단계로 나누어 확인했습니다.

```text
알림 생성 → DB 저장 → 사용자 식별 → WebSocket 전송 → STOMP 구독 → 화면 갱신
```

이를 바탕으로 다음 구조를 적용했습니다.

- DB를 통한 알림 기록 보존
- 사용자 전용 WebSocket 채널을 통한 실시간 전달
- 로그인 아이디를 공통 수신자 식별값으로 사용
- 연결 실패 시 5초 후 자동 재연결
- 알림 ID를 이용한 중복 화면 표시 방지
- 행위자 본인과 중복 수신자 제외

## 10. 실행 방법

### 요구 환경

- Java 11
- Oracle Database
- Maven
- Kakao Developers 애플리케이션

### 데이터베이스 설정

`src/main/resources/application.properties`에서 Oracle 접속 정보를 실행 환경에 맞게 설정합니다.

```properties
spring.datasource.url=jdbc:oracle:thin:@localhost:1521:xe
spring.datasource.username=사용자명
spring.datasource.password=비밀번호
```

### 카카오 OAuth2 설정

다음 환경변수를 등록합니다.

```text
KAKAO_CLIENT_ID=카카오 REST API 키
KAKAO_CLIENT_SECRET=카카오 Client Secret
```

카카오 Developers에서 Redirect URI를 다음 형식으로 등록합니다.

```text
http://localhost:8080/login/oauth2/code/kakao
```

### 애플리케이션 실행

Windows:

```bash
mvnw.cmd spring-boot:run
```

macOS 또는 Linux:

```bash
./mvnw spring-boot:run
```

실행 후 브라우저에서 다음 주소로 접속합니다.

```text
http://localhost:8080
```

## 12. 프로젝트를 통해 배운 점

기능을 구현하는 것뿐 아니라 기능이 필요한 이유와 업무 규칙을 먼저 정의하는 과정의 중요성을 확인했습니다.

프로젝트·이슈·댓글·상태 이력과 알림을 연결하면서 웹 애플리케이션의 화면, 서비스 로직, 데이터베이스와 실시간 통신이 하나의 흐름으로 동작하는 과정을 경험했습니다.

AI는 코드 초안 작성과 오류 원인 탐색에 활용했으며, 제시된 대안 중 프로젝트 목적과 데이터 구조에 적합한 방향을 직접 선택하고 기능과 DB 결과를 검증했습니다.

개발은 단순히 코드를 작성하는 작업이 아니라, 사용자의 문제를 이해하고 적절한 업무 규칙과 해결 구조를 선택하는 과정이라는 점을 배웠습니다.
